# 獣棋

動物ユニットを使ったタクティクスゲーム。配置フェーズでデッキを組み、バトルフェーズで相手の狐を倒せば勝利。

**▶ ブラウザでプレイ（WebGL）**：https://togemaru0616.github.io/WildTactics-/

> スクリーンショット・プレイ動画（後で追加予定）

## このゲームを作った理由

短い開発期間で完成させるため、「繰り返し遊べる・手軽に遊べる」を最低条件に設定した。
ストーリー重視の大作は期間的に無理と判断し、対戦＋ランダム地形生成で何度遊んでも
飽きにくい構造を選んだ。

候補は3案あった。

- **タイピング×魔法**：詠唱をタイピングで再現することで没入感を出す構想。好きなアイデアだったが、
  2Dゲームの枠に収まらないUXの作り込みが必要と判断して断念。
- **ブロック組立×戦車バトル**：ガチャで得たパーツ（L字ブロック・プッシュ機構など）を
  組み合わせて戦車を作り対戦するゲーム。ガチャが「強さの運」でなく「組み合わせの発見」に
  なるのが面白いと思っていた。2Dで作るには物理設計が複雑で断念。
- **リアルタイム将棋（採用）**：当時の自分が2Dゲームしか作れないという制約の中で、
  最も面白く作り切れると判断した案。将棋の「配置で勝敗が決まる」構造に
  リアルタイム行動を掛け合わせることで、戦略とスピード感を両立させた。

## 技術的なポイント

### ルールベース AI（P2コマンダー）

CPUは各ユニットの全合法手にスコアを計算し、優先度キュー順に行動する。  
視野内に敵がいれば **Combat**、いなければ **Explore** とモードをリアルタイムに切り替える。

#### スコア評価パラメータ

**戦闘モード（Combat）**

| パラメータ | 既定値 | 説明 |
|---|---|---|
| SafeAttack | 80 | 安全に攻撃できる手を積極的に選ばせるための基本スコア |
| RangeAttackBonus | 40 | 2マス射程（チンパンジー等）の攻撃に追加スコア。距離を保ちながら攻撃できる有利さを評価する。 |
| FoxDangerPen | 180 | **Foxのみ適用。** Foxが移動先で敵の射程に入るときの強ペナルティ。|
| DefenderFoxDist | 35 | Fox周囲3マス以内にいるユニットへの護衛ボーナス。Fox単独で戦わせないための誘導 |
| NumericalPowerMult | 12 | 数的劣位（少数側）に3.33倍ペナルティ。1体が多数に突っ込む孤立突撃を防ぐため |
| PressureBonus | 20 | HP優位時は前進・劣位時は後退を促す。優勢な側が積極的に押すと有利が加速するため |
| TerrainBonus | 20 | ユニットごとの得意地形への引き寄せスコア |
| CampBonus | 50 | HP低下時にキャンプへ誘導。20HP/6秒の回復機能を活かすための牽引スコア |
| SeekLastKnownBonus | 20 | 霧で見えなくなった敵の最終確認位置へ向かうボーナス。立ち止まらせないための誘導 |
| FormationSpreadPen | 18 | 縦方向に隊列が広がりすぎるとペナルティ。バラバラに動いて各個撃破されるのを防ぐ |
| FoxKillReward | 300 | SimBoard内で敵Foxを撃破したときの報酬。勝利条件を最優先させるため |
| DualAdvantageBonus | 40 | HP・数ともに優位なときの複合ボーナス。有利な状況でさらに攻勢をかけるための後押し |

**探索モード（Explore）**

| パラメータ | 既定値 | 説明 |
|---|---|---|
| ExploreNewTileWeight | 20 | 未探索タイルへの接近スコア。霧の中で敵を探させるための基本誘導 |
| ExploreLhGradient | 15 | 未制圧の灯台に近づくほど上がるボーナス。敵と接触がないときは灯台を目指させるため |
| ExploreFormationBonus | 18 | 索敵中でも隊列を保つボーナス。バラバラに散って各個撃破されるのを防ぐ |
| ExploreExposurePen | 25 | 索敵中に敵の射程に近づきすぎるとペナルティ。無防備な状態で敵に突っ込むのを防ぐ |

各ユニット（Tiger・Bear・Gorilla…）にはさらに個別乗数（AttackMult・CampMult・PressureMult 等）を設定して性格づけをしている。  
乗数は 1.0〜2.0 で、1.0 がデフォルト。例：FoxはCampMult=2.0、HorseはCampMult=1.6 と高めで回復志向を強め、LionやTigerは1.0のままで回復指向弱めという学習結果がでた。

#### Depth-2シミュレーション

近接敵（マンハッタン距離 ≤ 3）に対しては **1手先の敵応手** を計算し、その脅威をペナルティとして自手スコアから差し引く。

```
手のスコア = ScoreMove(自手) − 0.6 × EvalEnemyBestResponse(敵の即応手)
```

**設計の変遷：ミニマックス → NN → Greedy + Depth-2**

**① ミニマックス探索（廃止）**  
当初は将棋AIを参考に深さ8〜14のαβ探索を実装した。しかしリアルタイムゲームでは盤面が刻々変化するため、8ms かけて出した最善手が実行時点で最適でなくなることが多く廃止。

**② ニューラルネットワーク評価（廃止）**  
次にNNUEスタイルの盤面評価器（TinyNN）を実装し、AIの自己対戦データで学習させた。  
特徴量設計・ボルツマン探索・リプレイバッファまで作り込んだが、学習が安定せず、ルールベースより弱いまま改善しきれなかった。手作り評価関数に比べてデバッグが難しく、コストに見合わないと判断して廃止。

**③ Greedy + Depth-2（現在）**  
ScoreMove による瞬間評価と近接敵への1手先読み（Depth-2）のみで動作。余計な探索を取り除いたことでむしろ安定して強くなった。リアルタイム将棋では「深く読む」より「今を正確に評価する」方が有効という結論。

#### ユニット構成の選択（配置フェーズ）

CPUの配置フェーズでのユニット選択ロジック：

1. 各ユニット種について「ホーム領域から灯台に到達可能か」を計算（地形による移動制限の考慮）
2. `基本スコア + 到達可能タイル数 × 30` で評価し、灯台に到達できない場合は −50 ペナルティ
3. コスト合計 130 以内・最大 10 体の制約でスコア降順に貪欲選択
4. 選ばれたユニットをホーム領域にランダム配置

これにより地形が変わるたびにCPUの構成も変化する。

#### パラメータの最適化

パラメータの初期値は試行錯誤で仮決めしたあと、**AI同士の自己対戦シミュレーション**で改善した。

- 変異させたパラメータセットを過去の強いAI（最大5世代保持）と60
試合ずつ対戦させる
- 勝率50%超えで新チャンピオンに昇格
- 変異幅は序盤は大きく変異して広域探索、終盤は小さく収束

これを繰り返すことで、「なんとなく強そうな値」を出発点にAI同士の競争で洗練させた。

### オンライン対戦（Photon PUN2）

- 合言葉（キーワード）によるルームマッチング（JoinOrCreate方式）
- ホストがテレインシードを生成してルームプロパティに保存 → ゲストが同一マップを再現するシード同期
- 移動・ターン終了・ゲーム終了・リマッチを `RaiseEvent` で同期
- 霧システムの ViewingPlayer 分岐によりP1/P2それぞれの視界のみをレンダリング

## 苦労したこと

### ルールベースAIの制御

最も時間を費やしたのはP2（CPU）の行動制御。
「1体だけ突っ込む」「攻撃できるのに移動し続ける」といった問題が次々と発生し、
個体の動作を直せば集団としての整合性が崩れる、という繰り返しだった。

特に難しかったのは**集団として意思疎通しているように見せること**。
ユニットごとに独立したスコア評価だけでは群としての連携が生まれないため、
隊列維持・連携ボーナス・優先度キューによる行動順制御を組み合わせて
ようやく「それなりに戦える」レベルに到達した。
CPUを作ることの難しさを身をもって体験した部分。

また、当初は将棋AIをモデルにミニマックス探索を導入したが、リアルタイム性の強いゲームでは深い先読みが裏目に出ることが判明した。探索を廃止して瞬間評価（Greedy + Depth-2）に一本化したところ安定して強くなり、「ゲーム性に合った AI 設計」の重要さを実感した。
